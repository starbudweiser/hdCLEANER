# hdCLEANER — project context

Personal macOS disk cleaner, a take on AppYogi's Disk Cleaner (Pro Disk Cleaner): categories of junk with sizes, sub-list, Rescan / Clean, threshold monitor. Interface: follow the Socle design system.

## Architecture
- `Sources/HdCleanerCore`: no AppKit. `Scanner` (categories, one owner per path, `ScanContext` injected), `Cleaner` + `PathGuard` (last safety check before any deletion), `DiskInfo` / `ThresholdMonitor`, `AppSettings`.
- `Sources/hdCLEANER`: AppKit + SwiftUI window app (`MainView`, `SettingsView`, `About`, `AppModel`). When the monitor is on, closing the window keeps the app alive as a menu bar icon (`MonitorStatus`); at login `LoginAgent` (SMAppService agent, `Resources/LaunchAgent.plist`) starts it with `--monitor`, no window.
- Rules: regenerable categories are deleted (`Disposal.delete`), personal ones go to the Trash (`.trash`), system ones (`.admin`: `/Library/Caches`, `/Library/Logs`, `/var/log` rotated files, macOS installers, `.lproj` of third-party apps) and Time Machine snapshots (`.snapshot`, `tmutil`) go through ONE administrator-password script per cleaning (`AdminScript` → `AdminRunner`, osascript). Only regenerable, password-free categories are preselected, never an item of a running app. Browser data = caches only.
- `PathGuard` has three checks (`isSafe` home, `isSafeAdmin` system places, `isSafeAppBundle` uninstall); note Foundation normalises `/private/var` to `/var`, so system paths use `/var/log`. Tests inject `ScanContext.systemRoot` (never scan the real `/` in tests).
- Uninstaller (`Uninstaller`, "Applications" tab): app + related Library files by bundle id (and name when ≥ 5 letters), all to the Trash; app list loads names first, sizes progressively.
- Tools tabs (`Mode`: maintenance, permissions, invisibles): `MaintenanceTask` (scripts; `needsAdmin` → `AdminRunner.runCapturing`, else `ShellJob` with live output and cancel), `PermissionPlan` (builds a `find -x … -exec chflags/chown/chmod` script; order: clear flags → owner/mode/ACL/xattr → set flags; `PermissionGuard` refuses system trees, `/`, `/Users`, `/Volumes`…; `preview()` counts without changing anything), `InvisibleScanner`/`InvisibleCleaner` (items are re-checked against the roots and their exact names before deletion; volume system folders go through admin) and `InvisibleWatcher` (FSEvents → `cleanReported`, only `.DS_Store`, `._*`, `__MACOSX`). `AppSettings.watchedFolders` keeps the app alive in the menu bar (`keepsRunningWithoutWindow`).
- Permissions tab has two modes: simple (`AccessRepair.diagnose/plan`: counts items not owned by the user, locked via UF_IMMUTABLE/UF_APPEND, or without owner rw/rwx; plan = unlock, chown me, `chmod -N`, `u+rw` files / `u+rwx` dirs; re-diagnosed after repair; retry with admin when items remain) and advanced (`PermissionPlan` as is). Custom icons are never offered for deletion (`InvisibleKind.keepsCustomIcon`, `AppleDouble.hasCustomIcon` reads the Finder-info flag 0x0400). The window size is persisted (`WindowSize`) and the window is re-centered at each launch (no autosave name).
- Splash: `SplashScreen.swift` is the Socle model copied as is from nEXUSWATCH (+ a selftest preview hook); started in `AppDelegate.startSplash()` (not for `--monitor`, not in quiet selftest runs), the main window is held back with `.splashGated()`. `DiskArt.swift`: `DiskMark`/`AnimatedDiskMark` (splash icon, same shapes as `assets/make_icon.py`) and `DiskWatermark` (left column background). The live splash timeline (t = 0/2/4 s) has not been observed in the installed app.
- `TreeWalker` (fts) is used instead of `FileManager.enumerator` because Foundation hides `._*` files. FSEvents reports `/private/tmp/…` while `standardizedFileURL` yields `/tmp/…`: always normalise paths before comparing.
- Extra tools tabs (`Mode`: duplicates, map, organize; models in `ExtraTools.swift`, views in `ExtraToolsViews.swift`): `DuplicateFinder` (size → SHA-256 of the first 64 KB → full SHA-256; skips packages, `Library`, hard links; `DuplicateCleaner` always keeps one existing copy of the same size per group), `DiskMapper` (one fts pass → `MapNode` tree, small folders folded, files < 4 MB grouped as `smallFiles`; `Treemap.layout` = squarified), `Organizer` (loose files of one folder → one subfolder per type, never overwrites, `undo`). User files go to the Trash through `FileTrasher` behind `PathGuard.isSafeUserFile` (home or a mounted volume, never the boot volume alias). Never name a file-level view helper `help` (it resolves to `View.help` and recurses forever).
- Timeline tab (`Mode.timeline`; core `Timeline.swift`, app `TimelineTool.swift`): `TimelineModel` records free space every 30 min and one folder snapshot per day (`DiskMapper` on home folded at 50 MB → `Timeline.flatten`) while the app runs, into `~/Library/Application Support/hdCLEANER/timeline.json` (`TimelineStore`, bounded). `Timeline.growth` explains a rise by descending to the responsible folder, `forecast` = 14-day regression (days before full), `anomaly` = ≥ 5 GB lost in 3 days and ≥ 2× the 30-day pace → notification (`Notifier.fastFilling`, once a day). The selftest `render` seeds a fake history (`seedTimeline`).
- Security tab (`Mode.security`; core `Security.swift`, app `SecurityTool.swift`): engine = the `yara` CLI (4.6.0, BSD, universal binary built by `tools/build_yara.sh`, shipped in `Resources/`, copied by `build.sh`) run on Apple's own XProtect rules (`/Library/Apple/System/Library/CoreServices/XProtect.bundle/.../XProtect.yara`, kept up to date by macOS; the button runs `xprotect update` through `AdminRunner`) plus `Resources/hd_rules.yar` (startup-item heuristics; descriptions are English, the UI translates them by rule name). yara takes several rule files (namespaces `r0:`, `r1:`) but ONE target: `YaraEngine.scan` runs once per path. Real time = `SecurityWatcher` (FSEvents on ~/Library/LaunchAgents, /Library/LaunchAgents, /Library/LaunchDaemons, no work while nothing changes) → scan of the changed files → `Quarantine` (move to `~/Library/Application Support/hdCLEANER/Quarantine/<id>/payload` + info.json, exec bits removed, restorable; only user-owned places, system files are reported only). `AppSettings.realtimeProtection` (default on) keeps the app alive in the menu bar. Selftests: `--selftest security <dir>`, `--selftest securitywatch <fake home>`.
- Leftovers: folder named like a bundle id, vendor not matching any installed/running app, not Apple; never preselected.

## Commands
- Tests: `swift test`. App: `./build.sh` → `~/Applications/Applications Personnelles/hdCLEANER.app`.
- Real checks: `SELFTEST=1 ./build.sh`, then `build/hdCLEANER.app/Contents/MacOS/hdCLEANER --selftest library|apps <name>|e2e <fake home>|exclude <fake home>|watch <dir>|maint <non-admin task>|trash <file>|render <dir>` (`HDCLEANER_HOME` = fake home, also for launching the GUI; `HDCLEANER_QUIET=1` keeps the window behind, no focus; drive it with computer-use `app_*`).
- Languages (fr, en, es, it): `tools/strings_table.py` → `python3 tools/gen_strings.py`. Icon: `assets/make_icon.py`. Logo color ("hd" of the name): violet #A78BFA (`Brand`).
